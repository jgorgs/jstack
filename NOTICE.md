## What changed in the port

The port is editorial, not mechanical. [CHANGES.md](CHANGES.md) records each release's changes. Through 0.9.x the port kept its token rewrites, each with its reason, in pstack-claude's [`tools/substitutions.json`](https://github.com/michael-denyer/pstack-claude/blob/main/tools/substitutions.json).

Summary of structural changes:

- Plugin content lives at `plugins/jstack/` (with its own `.claude-plugin/plugin.json`). The repo root holds `.claude-plugin/marketplace.json` and the LICENSE / NOTICE / README / CHANGES docs.
- `.claude-plugin/marketplace.json` added at repo root so the repo is installable via `/plugin marketplace add`. The marketplace's single plugin entry sources from `./plugins/jstack`.
- `plugins/jstack/.codex-plugin/prompts/<name>.md` stubs added so each public skill is reachable as a slash command on Codex. Claude Code needs no stubs: the skill itself serves `/jstack:<name>`.
- Six skills imported from `cursor-team-kit`: `deslop`, `make-pr-easy-to-review`, `fix-ci`, `fix-merge-conflicts`, `get-pr-comments`, `what-did-i-get-done`. All copied verbatim — no rewiring needed.
- Three skills and two agents imported from `thermos`: `thermos`, `thermo-nuclear-review`, `thermo-nuclear-code-quality-review`, `thermo-nuclear-review-subagent`, and `thermo-nuclear-code-quality-review-subagent`. The skills' `subagent_type` values take the `jstack:` namespace, and the agents' parent-orchestration notes name Claude Code's tools.
- `plugins/jstack/skills/babysit/` is independently authored as the Claude Code analog of Cursor's `/babysit` built-in. It has no upstream pstack equivalent; its workflow is informed by Cursor's public `/babysit` behavior. No code or prose was copied from any source.
- `plugins/jstack/skills/jedi-mode/scripts/` is vendored from upstream (`watch-pr`, `orch`, `bootstrap.ts`, `package.json`, `bun.lock`). `worktree-audit.mjs` is a port-only rewrite of upstream's `worktree-audit.sh`; it reads the Claude Code, Codex, and Pi transcript directories instead of Cursor's and reports prunable worktrees. Port edits: `bootstrap.ts` fails clearly under node and installs production dependencies only; `orch/store.ts` and `orch/orch.test.ts` carry the silent-failure fixes from #35; `package.json` typechecks the whole tree; `tsconfig.json` is port-only. Everything else is upstream's code under the upstream MIT license.
- JStack 2.0.0 renames upstream's `poteto-mode` and `poteto-help` skills and its `poteto-agent` agent to `jedi-mode`, `jedi-help`, and `jedi-agent`. The paths in this notice use the new names. The rename also edits the vendored scripts: the package name in `package.json` and `bun.lock`, the install marker and bun error message in `bootstrap.ts`, and a fixture branch name in `orch/orch.test.ts`.
- `plugins/jstack/agents/comment-sicko.md` is upstream's `Comment Sicko` agent, renamed to `comment-sicko` so the name works as a Claude Code `subagent_type`. The body is verbatim.
- A Codex build shares the same `skills/` tree. It adds `plugins/jstack/.codex-plugin/plugin.json`, a root `.agents/plugins/marketplace.json`, and `plugins/jstack/skills/jedi-mode/references/codex-tools.md` (the Claude-to-Codex tool, model, built-in, and per-skill map). Affected skill entry points link to this map so direct invocation works without the optional Codex prompt stubs. See the [reference](docs/reference.md#codex).

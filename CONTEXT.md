# CONTEXT — domain glossary

Names for the concepts this repo's design discussions keep reaching for. Architecture reviews use these terms; if a review needs a concept that isn't here, add it.

- **Build** — one of the runtimes the plugin ships to: the Claude Code build (`.claude-plugin/`), the Codex build (`.codex-plugin/`), the Pi build (the repo-root `package.json` and the extension in `plugins/jstack/pi/`), the GitHub Copilot build (the Claude Code manifests read by the Copilot CLI and app, with its own hook context, `PreToolUse` checks, and mapping), and the native Agent Skills paths for Prime Agent, opencode, and Gemini CLI (`~/.agents/skills/` symlinks). All builds share one `skills/` tree. Skills keep upstream's Claude-native wording, and the Codex, Pi, and Copilot builds resolve tool names through `skills/jedi-mode/references/codex-tools.md`, `pi-tools.md`, and `copilot-tools.md`, because rewriting them in tool-neutral language would fork every upstream skill. Runtime-specific execution adapters, such as the Pi extension, stay separate from discovery.
- **Agent Skill** — one directory under `plugins/jstack/skills/` with portable `name` and `description` frontmatter. Codex, Prime Agent, opencode, and Gemini CLI discover this shared tree natively. Runtime-specific keys may affect visibility only where that runtime understands them.
- **Model policy** — the mapping from roles to model slugs. Defaults live in `plugins/jstack/models.json` and are stamped into each skill's Models section; the user's override sheet (`jstack-models.md`, written by `setup-jstack` at a per-runtime path) is the layer that adapts them at runtime. Codex and GitHub Copilot keep their own sheets. Copilot ships no default slugs, so its sheet is required before a skill dispatches on role models.
- **Role** — a named unit of delegated work with its own model choice (`arena runners`, `how critics`, `swarm workers`). The role vocabulary lives in `models.json` and surfaces in `setup-jstack`'s sheet.
- **Panel** — the three-model diverse panel the multi-model skills (`arena`, `architect`, `interrogate`, `how`) run by default. One fact in `models.json`; the generator stamps every copy and fails on strays.
- **Prompt stub** — an optional Codex slash command that invokes a skill. The generator writes it under `.codex-plugin/prompts/` using the skill's row in the [slash-command reference](docs/reference.md#slash-commands). Native skill discovery works without it.
- **Menu description** — the short description in a public skill's row in the [slash-command reference](docs/reference.md#slash-commands). Codex displays it in the slash menu. The skill's frontmatter `description` tells the agent when to invoke it.
- **Generator** — `tools/generate.mjs`. Stamps facts from their single source into every committed copy and validates cross-file contracts. CI runs it with `--check` and fails on any stale copy.
- **Generator-owned copy** — a committed value written by the generator, such as a manifest version, prompt stub, or Models section. Regeneration overwrites hand edits, and CI catches any difference.
- **VERSION** — the repo-root file holding the canonical plugin version. Releases edit it, add the matching `CHANGES.md` heading, and regenerate; plugin auto-update installs by this number.
- **Upstream review** — the by-hand way JStack takes changes from pstack-claude. [UPSTREAM.md](UPSTREAM.md) records the last upstream commit reviewed and the procedure; the `upstream-review` skill runs it and lists the changes worth copying.
- **Invariants** — layout and flag rules enforced inside `tools/generate.mjs` (`agentSkills`, `validatePluginLayout`); `tests/invariants.test.mjs` proves each can fail against fixture trees. `tests/skill-collision-repro.sh` is the one behavioral check, needing the `claude` CLI.
